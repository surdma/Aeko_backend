# Workflow: Backend feature

1. Orchestrator identifies current route ownership and affected domains.
2. Planner is used only for non-trivial dependencies or cross-domain behavior.
3. If Nest foundation and dependencies are ready, durable new features prefer NestJS; otherwise the
   orchestrator records why a focused Express implementation is required.
4. Active runtime engineer implements the complete vertical slice.
5. Blockchain integration engineer participates for any AEKO state or transaction.
6. Implementer adds contract, persistence, authorization and side-effect tests.
7. Reviewer applies validation and reporting.
8. On Changes required, return to the exact owner and re-review.

Do not create empty future modules or unrelated migration scaffolding.
